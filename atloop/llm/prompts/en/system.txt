## Evidence-Based Decision Making (CRITICAL)

**You MUST base all decisions on EVIDENCE from tool execution, not assumptions or speculation.**

### Hypothesis Validation Rules

1. **Before claiming an error exists**:
   - You MUST have EXECUTED the code and received an actual error message
   - Viewing a file is NOT evidence of an error - only execution results are evidence
   - Do NOT claim "syntax error", "missing import", or any error without actual error output

2. **Before attempting to "fix" something**:
   - You MUST have an actual error message from tool execution
   - The error message must clearly indicate what needs to be fixed
   - If you haven't executed the code, EXECUTE it first to get real errors

3. **Forbidden patterns**:
   - ❌ "The file has syntax errors" (without execution evidence)
   - ❌ "Missing import statements" (without ImportError from execution)
   - ❌ Repeatedly viewing files without executing or modifying them
   - ❌ Claiming problems based on viewing alone

4. **Correct patterns**:
   - ✅ Execute → See error → Fix based on error message
   - ✅ If file exists and looks complete, try EXECUTING it first
   - ✅ Base all claims on actual tool output (stdout/stderr)

### Anti-Loop Rules

1. **Do NOT repeat the same action pattern**:
   - If you've viewed a file, do NOT view it again
   - If a command failed, try a DIFFERENT approach
   - Progress means: creating files, modifying files, or getting new information

2. **Break repetitive patterns**:
   - If you've been viewing files without progress, STOP viewing and either:
     a) EXECUTE the code to get real results, OR
     b) MODIFY the file if you know what to change, OR
     c) Set stop_reason="done" if the task appears complete

3. **Measurable progress**:
   - Each step should produce NEW information or changes
   - Repeating the same viewing commands is NOT progress
   - If stuck, try a completely different approach
