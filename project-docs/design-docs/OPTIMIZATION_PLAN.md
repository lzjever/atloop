# Memory 模块优化实施计划

## 一、已实现的基础优化

### ✅ 1. 记忆压缩机制
- **文件**: `titan/memory/compressor.py`
- **功能**: 自动压缩旧的 attempts 和 decisions，防止无限增长
- **配置**: 
  - `ATTEMPTS_KEEP_RECENT = 10`
  - `DECISIONS_KEEP_RECENT = 5`
- **触发**: 每步自动检查并压缩

### ✅ 2. 重要性评分器
- **文件**: `titan/memory/scorer.py`
- **功能**: 为决策、里程碑、经验等评分（0.0-1.0）
- **用途**: 未来可用于优先保留高分记忆

### ✅ 3. 智能截断
- **改进**: `titan/memory/summarizer.py`
- **策略**: 优先保留长期记忆和最后错误信息

## 二、待实施的优化（按优先级）

### 🔴 高优先级（立即实施）

#### 1. 结构化 Plan ⚠️ **重要**
**问题**: 当前 `plan` 是字符串，无法跟踪步骤状态

**实施**:
```python
# titan/memory/plan.py
@dataclass
class PlanStep:
    id: str
    description: str
    status: str = "pending"
    completed_at_step: Optional[int] = None
```

**收益**: 
- LLM 可以准确判断进度
- 避免重复执行已完成步骤
- 支持计划步骤依赖关系

**工作量**: 2-3 小时

#### 2. 在截断中使用重要性评分 ⚠️ **重要**
**问题**: 当前截断不考虑重要性，可能丢失关键记忆

**实施**:
- 在 `MemorySummarizer.summarize()` 中
- 使用 `ImportanceScorer` 评分
- 优先保留高分记忆

**收益**: 
- 关键信息不会被截断
- 更好的记忆质量

**工作量**: 1-2 小时

### 🟡 中优先级（后续优化）

#### 3. 记忆检索机制
**功能**: 根据当前上下文检索相关记忆

**实施**:
- 基于关键词的简单检索（初期）
- 可选：基于 embedding 的语义检索（后期）

**工作量**: 3-4 小时

#### 4. 记忆去重
**功能**: 检测并合并相似的记忆项

**实施**:
- 使用内容哈希或相似度计算
- 合并重复的决策/里程碑

**工作量**: 2-3 小时

### 🟢 低优先级（可选）

#### 5. Embedding 检索
**功能**: 使用向量数据库进行语义检索

**依赖**: `sentence-transformers` 或类似库

**工作量**: 4-6 小时

#### 6. LLM 重要性评分
**功能**: 使用 LLM 评估记忆重要性（更准确但成本高）

**工作量**: 2-3 小时
